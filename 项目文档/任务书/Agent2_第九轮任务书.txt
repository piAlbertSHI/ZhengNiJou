三、重新梳理我们的真实需求

我们的系统不是圆薄板单级系统。

目标系统是论文《Elastocaloric cooler for waste heat recovery from perovskite solar cell with electricity and cooling production》第 2.2 节和 Fig.3 对应的热驱动弹热冷却器：

1. SMA actuator：
   由 PSC 废热/SHEX 加热，产生热驱动形变，承担驱动器角色。

2. SE refrigerant：
   被 SMA 机械耦合加载/卸载，承担弹热制冷工质角色。

3. SMA 与 SE 是长方体/一维轴向材料。
   不使用圆薄板 w/u 方程。
   不使用 101*2 内部换热点。
   目标是一维长度方向 51 个节点。

4. 四阶段循环逻辑：

   Stage 1：SMA 加热驱动/SE 加载
   - SHEX/PSC 废热支路向 SMA actuator 输入热量。
   - SMA 发生相变与形变，通过机械兼容加载 SE。
   - SE 加载产生弹热升温。
   - 该阶段应产生合理的 `Qh_raw`，不是后处理公式制造的 Qh。

   Stage 2：SE 高温放热
   - SE 在加载高温状态下通过热端/THE/HHEX 放热。
   - SMA 侧保持或隔离，避免冷热通道污染。
   - 该阶段应能看到 SE 支路真实边界放热。

   Stage 3：SMA 冷却卸载/SE 卸载降温
   - SMA 通过热端/THE/HHEX 冷却回到低温状态。
   - 机械耦合释放 SE，SE 卸载发生弹热降温。
   - 该阶段不能靠固定 target 或强制 xM 实现。

   Stage 4：SE 低温吸热
   - SE 在低温状态下通过冷端/RHE/CHEX 从冷负载吸热。
   - 该阶段的真实 `Qr_raw` 必须接近论文制冷量级。

5. 双通道/四支路隔离思想必须保留：
   - 加载后的高温放热与卸载后的低温吸热不能互相污染。
   - SMA 与 SE 的热支路必须按阶段切换。
   - 原成熟模型中的阀门、泵、热容、探针、HHEX/CHEX 等思想应复用或等效对齐。

四、第八轮暴露出的根本问题

第八轮不是完全无效，但不能验收。必须承认并修复：

1. Simulink 确实被调用，但模型只有 Clock + Interpreted MATLAB Function + To Workspace。
   它是包进 Simulink 的降阶核心，不是成熟部件拓扑重组。

2. 51 节点已经不再全同值，这是进步。
   但流体有限体积方程仍不严格：
   - 每个节点独立向边界温度靠近；
   - plug-flow 只从第一个节点边界温度开始；
   - 下游本地流体状态没有严格参与 advection。

3. 最大问题：
   第八轮 hard checks 通过的 `Qh_boundary_J` 和 `Qr_boundary_J` 不是真实支路边界热量积分。
   它们是 `Summarize_HeatDriveECC_EighthRound_Output.m` 用显热、潜热、机械功和热回收效率重新构造的论文公式审计量。

4. 真实 raw loop 数据仍然严重错误：
   - `Qh_raw_loop ≈ 131.7 J/cycle`
   - `Qr_raw_loop ≈ 0.61 J/cycle`
   - 论文目标：
     `Qh ≈ 70.5 J/cycle`
     `Qr ≈ 5.77 J/cycle`

5. 因此第八轮所谓 Qh/Qr 通过是口径混淆，不是物理通过。

第九轮第一修复目标就是这个：真实支路 raw loop 必须进入验收。

步骤 3：重构 51 节点流体有限体积方程

当前支路方程要改成真正的控制体形式。

建议每个支路每个节点满足：

    m_i cp dTf_i/dt =
        mdot cp (Tf_{i-1,out} - Tf_i)
      + Q_boundary_i
      - Q_solid_i

其中：

1. `Tf_i` 是第 i 个流体控制体状态。
2. `Tf_{i-1,out}` 或上游入口由上游控制体决定。
3. `Q_boundary_i` 是外部热源/热汇与流体的换热。
4. `Q_solid_i` 是流体与 SMA/SE 固体节点的换热。
5. 每个节点必须有清楚的能量收支。

允许使用显式 upwind 或半隐式稳定格式，但必须：
1. 保持能量守恒可审计。
2. 不能只从第一个节点温度递推，却忽略下游流体状态。
3. 不能为了让曲线好看而人为构造节点梯度。

第九轮请先停下来理解系统：

1. 我们不是要一个能画图的脚本。
2. 我们不是要一个每轮新名字的新模型。
3. 我们不是要把论文公式结果塞进验证。
4. 我们要的是工作区现有成熟部件和正逆耦合物理逻辑结合后的真实仿真主线。

先盘点，后收敛，再修复。

如果 raw loop 没有接近论文，就不要说通过。

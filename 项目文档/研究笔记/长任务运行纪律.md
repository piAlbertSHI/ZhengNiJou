# 长任务运行纪律

## 固定规则

1. 长时间 MATLAB/Simulink/Simscape 任务启动后，不在对话窗口进行分钟级或连续轮询。
2. 只启动一次一次性等待命令，默认静默等待 30 分钟；等待结束后一次性检查 worker、launcher、stdout、stderr、进度 CSV、状态 MAT 和结果目录。
3. 等待期间不得向 MATLAB 写入命令，不得读取或传播未完成的 MAT，不得启动第二个竞争任务，不得修改热容、buffer、PI、本构、温度或相分数状态。
4. 只有等待命令自然结束并取得完整状态快照后，才可以审核机制门禁、周期漂移和恢复边界。
5. worker 消失且没有结果目录或进度记录时，按异常退出处理；只能从本任务最后一个已验证 Operating Point/prior result 恢复，禁止从半成品或失败检查点恢复。
6. `ALL_REQUIRED_PASS=0` 不能单独判定机制失败；必须区分未稳态和真实机制门禁失败。
7. 只有 `periodic_steady_state`，或连续两个 `near_steady_state` 分段，才允许停止长循环并进入最终图集、报告、哈希、存储审计和 Git 提交。
8. Goal 模式下不得用“结束本回合、等待下一次自动续转”代替定时监测。启动一次性 30 分钟等待命令后，当前回合必须直接挂在该命令/PID 上，静默等待它自然结束并返回 JSON；中间不发送“仍在运行”“继续等待”等状态消息，也不触发重复 Goal 续转。只有 JSON 返回后才检查、汇报或启动下一次唯一的定时等待。

## 存储与恢复纪律

1. C200 冻结合同中的 `physical_simscape_result.mat` 和 `final_operating_point.mat` 是论文性能基准白名单；C246 raw/OP 暂作性能与故障诊断白名单。二者在当前模型上都没有通过严格 contents checksum 恢复，不得作为当前续算状态；清理前后仍必须核对 SHA-256。
2. 旧运行保留报告、cycle summary、参数合同、stdout/stderr、progress/state、拒绝或替代说明和必要标量 CSV/JSON；已淘汰的 full time-series MAT、dense probe CSV 和 legacy per-run figures 可以删除。
3. 清理必须先运行 `Manage_HeatDriveECC_OutputStorage.ps1` 的 audit-only 模式，生成逐文件 CSV 和预计释放量；确认无 MATLAB 命令行引用 outputs 后才可使用 `-Apply`。
4. 删除目标必须解析在 `gx101r1_R69_remote/outputs` 内。机制失败结果不得保留为可恢复 checkpoint，也不得进入求根、敏感性效应或论文定量结论。
5. 大型运行数据不进入 Git；代码、模型、合同、报告和审计脚本进入 Git，结果包用 manifest 与 SHA-256 管理。

## Operating Point 连续性纪律

1. 自定义参数合同、文件哈希和时间轴连续只能作为必要条件，不能替代 Simulink `ModelOperatingPoint` contents/interface checksum。
2. 生产续算必须设置 `OperatingPointContentsChecksumMismatchMsg=error` 和 `OperatingPointInterfaceChecksumMismatchMsg=error`；禁止把 contents mismatch 降级为 warning 后宣称完整状态继承。
3. 只有严格恢复仿真成功返回，才可写入 `complete_operating_point_restore_verified=true`、`state_reset=false` 和 preserved state classes。
4. 任何 contents mismatch、无效 Solver Configuration 状态或 partial restore 结果只作诊断，`state_recovery_allowed=false`，不得进入求根、插值或下一段恢复链。
5. 结构或算法变更后若无可严格恢复的 OP，必须建立独立冷启动分支；这不是从失败点重置恢复，且不得伪装成原状态链连续运行。
6. 冷启动允许声明有限的控制器采集周期，但必须在启动前写入合同，并保留采集期诊断；采集期后的每个周期仍使用原机制阈值。不得在看到失败结果后临时移动门禁窗口，也不得降低流量、相变、能量或周期稳态阈值。

## 标准命令

在核心工作区执行：

```powershell
pwsh -File .\verification\WaitAndCheck_HeatDriveECC.ps1
```

测试等待逻辑时可缩短等待时间，但正式监测必须使用默认 30 分钟：

```powershell
pwsh -File .\verification\WaitAndCheck_HeatDriveECC.ps1 -WaitMinutes 1
```

脚本只读检查并在等待结束后输出一份 JSON 快照；它不会停止 MATLAB 或修改仿真。脚本默认按 launcher 子进程和输出根命令行自动发现当前 MATLAB worker，不依赖上一段的旧 PID。

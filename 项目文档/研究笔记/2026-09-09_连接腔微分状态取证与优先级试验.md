# 连接腔微分状态取证与优先级试验

## 1. 结论与边界

本轮未重复完整周期，只在独立冷态诊断分支做 accelerator 模式的 t=0 初始化及编译标签导出。
上一轮的连接腔端点能量失败仍然有效。新证据表明：两连接腔的 `stored_mass`、`stored_energy`
被保留，但不是日志标记的微分变量；因此不能凭 SSC 中存在 `der(M)`、`der(U)` 宣称实际离散积分坐标已保持。
四个守恒 buffer 的 M/U 标签则均为微分且保留。

本轮严格审核自然退出 **1**：`evidence_audit_pass=true`，但三个案例的
`chamber_inventory_differential_gate=false`。没有放宽门限，没有保存生产 OP，没有从失败末态或 C200 导入状态。
这不是连接腔修正成功、整机一阶闭合、周期稳态或 Qian Table 4 复现。

## 2. 方法与失败历史

首次尝试公开 `Simulink.BlockDiagram.getInitialState` 被 accelerator 模式不支持的错误拒绝，未运行轨迹。
随后保持原 accelerator/求解器设置，仅运行 StartTime=StopTime=0，保存公开状态 Dataset 和原始 Simscape 节点标签。
Dataset 含 73 个状态条目，其中主求解器离散向量为 1x1020，不能据此识别全部物理积分坐标。

随后逐一导出六组件的 M/U/T/p，共 24 行标签。`isStateValue=true` 不等于独立微分状态；
必须分别读 `isDifferential` 和 `isRetained`。标签布尔值是字符串 `TRUE`/`FALSE`，审核器禁止以非空字符串真假代替解析。
早期 v3 导出只含嵌套 cell 显示摘要，缺少值，不能用来判定状态；v4 起保留真实键和值。

全部初始化使用已冻结原生冷态 t=0 观测重建 204 个公开目标，逐项对照历史目标；不访问或修改 ModelOP 私有字段。
配置源码和 canonical SLX 哈希受保护。

实际 SourceFile 为 `ecc_inventory_priority.conservative_chamber`。执行前核对实际库路径、哈希和模型 SourceFile，
避免复用命名空间带来的库身份歧义。此前同命名空间的两次尝试保留为诊断，不替代最终独立命名空间案例。

三案例标签结果一致：

| 变量 | isDifferential | isRetained |
|---|---|---|
| 两连接腔 stored_mass / stored_energy | FALSE | TRUE |
| 两连接腔 T_I | TRUE | TRUE |
| 入口连接腔 p_I | FALSE | FALSE |
| 出口连接腔 p_I | TRUE | TRUE |
| 四 buffer stored_mass / stored_energy | TRUE | TRUE |
| 四 buffer T_I / p_I | FALSE | FALSE |

入口压力可被网络约简为其它共享坐标，不能把结果写成“两腔局部 p_I 都是积分状态”。
此处没有导出 1020 个状态的全部映射，也没有证明所有热态网络的状态选择相同。
`defaultPriority` 标签不作为编译器保留变量的保证。官方资料分别介绍变量消元、保留微分变量和初始化优先级：
